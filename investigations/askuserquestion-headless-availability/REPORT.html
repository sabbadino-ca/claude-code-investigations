Is AskUserQuestion available in a plain claude -p run?

Question

This is a behaviour to observe, not a doc claim. In headless mode (claude -p), is AskUserQuestion left out of the tools offered to the model by default? Does --permission-prompts none or --permission-mode dontAsk change that?

Recorded for each run:

  • The system:init tools list and permissionMode from the stdout stream-json.
  • From the session .jsonl: the result of ToolSearch select:AskUserQuestion, which checks whether it is a deferred tool, and the result of a direct AskUserQuestion call.
  • PreToolUse/PostToolUse/PostToolUseFailure/PermissionRequest hook events.
  • The result message's permission_denials, the exit code and stderr.

Run mode: claude -p only.

  • availability.ts is the driver. The runs pass no --allowedTools, no --permission-prompt-tool and no MCP config, so the only difference between scenarios is the scenario flag.   • Env: ISOLATION_ENV only. Inherited CLAUDE* vars are stripped.

  • The init tools list had 30 entries in every session that started, ToolSearch among them, and never AskUserQuestion. The list was the same across scenarios.
  • When the model called the tool anyway, the CLI answered with an is_error tool_result and fired no hook (no PreToolUse, no PermissionRequest). permission_denials stayed []. The tool is rejected as non-existent, not denied by the permission system.
  • The error text says the tool is disabled "in subagents as well as here", that is, for the whole session.
  • The summary's "other session mentions" column shows 2 for each session. Both are copies of the probe prompt itself, in queue-operation and api-request-blob entries, not a tool listing. The driver's filter doesn't exclude those entry types. The LISTED= self-reports are unreliable: in two runs the model printed deferred, then corrected itself to absent.
  • Each session cost about $0.01 and took 5–9 s.

Conclusion

Yes. On Claude Code 2.1.317, claude -p removes AskUserQuestion by default. It is not in the init tool list, not loadable through ToolSearch, and a direct call returns "No such tool available … disabled for this session". Neither --permission-prompts none nor --permission-mode dontAsk brings it back.

For contrast, the askuserquestion-relay investigation, on CLI 2.1.296/2.1.299, got AskUserQuestion offered in -p when it passed a --permission-prompt-tool, a permission host. That was not re-tested here.

Not tested

  • A positive control in this folder: --permission-prompt-tool <mcp tool>, --permission-prompts host with such a tool, --input-format stream-json, or --allowedTools AskUserQuestion / --tools AskUserQuestion.
  • Other permission modes: acceptEdits, auto, bypassPermissions, manual, plan.
  • The Agent SDK and interactive mode.
  • The exact tool definitions sent to the API. The session log's api-request-blob entries hold the messages but not the tool schemas, so the evidence is the init list, ToolSearch and the call error.
