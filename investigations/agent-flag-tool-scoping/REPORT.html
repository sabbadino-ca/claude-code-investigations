With --agent, does each thread get exactly the tools its tools: field declares?

Question

A behaviour to observe. Main runs as an agent (claude -p --agent main-star) and launches two subagents. Every thread declares its built-in tools and whole MCP servers in its own tools: field, and all three MCP servers are defined in the project .mcp.json. Does each thread get exactly what it declares, nothing more and nothing less? In particular, can a subagent get a built-in tool and an MCP server that main's allowlist leaves out? In other words, does main's allowlist cap its subagents?

The docs, code.claude.com/docs/en/sub-agents, give the syntax for a whole MCP server in tools:

Give the subagent every tool from one server | tools | mcp__github__*

They also describe the subagent pool as narrowed from main's, without saying what happens when main itself is restricted by --agent:

Subagents inherit the built-in tools and MCP tools available in the main conversation, narrowed by two filters [...] To restrict tools, use the tools field as an allowlist [...] tools is resolved against the remaining pool.

Pass --agent <name> to start a session where the main thread itself takes on that subagent's tool restrictions and model

What is recorded, for each thread (main, sub1, sub2):

  • Visible tools: every tool name sent in the thread's API requests (api-request-shape entries of its transcript) plus every deferred tool name (deferred_tools_delta attachments). This set is compared with the declared set and every missing or extra tool is listed.
  • ToolSearch and deferral: no thread declares ToolSearch. The user's expectation is that ToolSearch is then absent and every MCP tool is sent from the start, with no deferred list.
  • Usable tools: each thread runs the same probe. It calls every mcp__ tool it sees (each returns an unguessable NONCE), runs echo BASH_RAN if it has Bash, reads read-me.txt (READ_NONCE) if it has Read, and writes a file with WRITE_NONCE if it has Write.

Every probed tool is pre-approved with --allowedTools and dontAsk, so a tool that is absent is really not offered. It can't be a permission denial in disguise. Run mode: claude -p only.

Syntax order (agreed with the user): first the documented mcp__<server>__*. Only if that fails, a second run with mcp__<server>.

Setup

.mcp.json: alpha, beta, gamma   (each: tool_one, tool_two)

main  (claude -p --agent main-star)   tools: Agent, Bash, mcp__alpha__*
  --Agent (foreground)-->  sub1-star  tools: Read,  mcp__beta__*
  --Agent (foreground)-->  sub2-star  tools: Write, mcp__gamma__*

Main has no Read, Write, beta or gamma. If sub1 and sub2 still get theirs, main's allowlist doesn't cap subagents. If main's Bash or alpha appear in a subagent, the subagent's tools: doesn't fully restrict it.

  • .mcp.json: the three project MCP servers. They are approved through enabledMcpjsonServers in .claude/settings.json and in the driver's --settings.
  • nonce-mcp.mjs: a stdio MCP server, started once per server name. tool_one and tool_two each return a fixed unguessable nonce. Two tools per server show that * brings in all of them.
  • .claude/agents/main-star.md: main's agent, tools: Agent, Bash, mcp__alpha__*. Agent is needed to launch the subagents.
  • .claude/agents/sub1-star.md: tools: Read, mcp__beta__*. Both are outside main's allowlist.
  • .claude/agents/sub2-star.md: tools: Write, mcp__gamma__*. Both are outside main's allowlist.
  • read-me.txt: holds READ_NONCE, which proves a Read went through.
  • prompts/probe.md: the probe every thread runs.
  • prompts/main.md: main's script. Main runs the probe itself (step A), launches sub1 and then sub2 in the foreground with the same probe (step B), and relays the replies (step C). The subagents run in the foreground, so the background filter of built-in tools plays no part (and Read, Write and Bash would survive it anyway).
  • tool-scoping-cli.ts: the driver.
    • It spawns the installed claude -p --agent main-star --setting-sources project --model sonnet --allowedTools Agent Bash Read Write ToolSearch mcp__alpha mcp__beta mcp__gamma --permission-mode dontAsk.
    • It logs hooks (PreToolUse, PostToolUse, PostToolUseFailure, SubagentStart, SubagentStop) and parses the stream-json.
    • From the transcripts it reads each thread's visible tool set, judges it against the declared set, and writes <scenario>.verdict.json and a summary.
  • Env: CLAUDE_CONFIG_DIR and CLAUDE_CODE_PROJECT_DIR_NAME=sessions, from the harness. Inherited CLAUDE* vars are stripped.

  • Nothing leaked between threads.
    • Read, Write, beta and gamma were absent from main.
    • Main's Bash and alpha tools were absent from both subagents.
    • Each subagent lacked the other's tools.
    • No thread called a tool outside its declared set. sub1 said: "I have no Bash or Write tool, so I skipped steps 2 and 4."
  • ToolSearch: absent everywhere. The MCP tools were sent inline from the first request and the deferred-tool list was empty in every thread, as the user expected.
  • The two extras, present in every thread whatever it declares, both with defer_loading: true:
    • DeferredToolPlaceholder: "Reserved placeholder that keeps deferred tool loading active; never call this tool."
    • advisor: a server tool of type advisor_20260301, model claude-opus-5-5.
    Neither was called, and with no ToolSearch neither can be loaded. The tools: field does not control them.
  • The stream-json system:init tools of main read ["Task","Bash","mcp__alpha__tool_one","mcp__alpha__tool_two"], which is the same set under Agent's older name Task, without the two hidden tools.

Conclusion

Yes, on Claude Code 2.1.311 with claude -p --agent. Each thread gets exactly the built-in tools and MCP servers its own tools: field declares. The only exceptions are two hidden harness tools (DeferredToolPlaceholder, advisor) that every thread gets regardless.

  • Main's allowlist does not cap subagents. A subagent's tools: is resolved against the session's full pool: every built-in tool and every server in .mcp.json. It is not resolved against main's restricted set. sub1 got Read and beta, and sub2 got Write and gamma, though main had none of them. The doc sentence "Subagents inherit the [...] tools available in the main conversation" therefore doesn't hold in this case, where main itself is restricted by --agent.
  • Main gets exactly its agent's tools:, so --agent does restrict main.
  • The one-line syntax for a whole MCP server is the documented mcp__<server>__*. It works in an agent used as main and in subagents.
  • Without ToolSearch in tools:, MCP tools are loaded up front, not deferred.

Not tested

  • The mcp__<server> form without __* (not needed, since __* worked). The docs say that form matches nothing in tools for a server whose name contains __.
  • A subagent with no tools: field under --agent: does it inherit main's restricted set or the full pool?
  • Threads that declare ToolSearch (MCP tools deferred).
  • Background subagents, nested subagents, forks, and disallowedTools.
  • MCP servers defined outside .mcp.json: --mcp-config, user scope, a subagent's mcpServers, claude.ai connectors (connected in the session but absent from every thread here).
  • The interactive terminal and the Agent SDK.
  • A single run; the tool sets come from the harness, not the model, so they should not vary between runs.
