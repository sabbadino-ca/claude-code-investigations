Unquoted colon in an agent or skill description

Question

A behaviour to observe, with no doc claim tested. Agent and skill files start with YAML frontmatter (sub-agents, skills). In strict YAML, an unquoted : (colon then space) inside a plain value is a syntax error ("mapping values are not allowed here"):

description: Test-harness agent ... never needed note: TAIL=... for real work.

Does Claude Code accept such a description whole, cut it at the colon, drop the agent or skill, or report an error?

Recorded, with no model judgement:

  • The session .jsonl attachments agent_listing_delta and skill_listing, which hold the exact listing text the model receives.
  • The agent and skill names in the stream-json system:init.
  • The --debug-file log, searched for parse warnings.

Run mode: headless claude -p only.

Setup

claude -p (Haiku), prompt "reply OK", no tool calls; only the listings computed at session start are read

Each description has HEAD=<n> before the colon and TAIL=<n> after it, so the listing text shows where a description stops if it is cut. The agents put tools: Read after the description, so the (Tools: …) suffix of the agent listing shows whether the frontmatter after the bad line still parsed.

  • .claude/agents/colon-agent.md: the description contains note: TAIL=… (invalid strict YAML), followed by tools: Read.
  • .claude/agents/control-agent.md: the same sentence without the colon (the baseline).
  • .claude/skills/colon-skill/SKILL.md: the same pattern for a skill.
  • .claude/skills/control-skill/SKILL.md: the skill baseline without the colon.
  • prompts/main.md: "Do not call any tool. Reply with the single word OK."
  • colon-cli.ts: one claude -p run with --debug-file. It extracts each fixture item's listing line(s) from the session log, checks for HEAD, TAIL and the tools suffix, and collects matching debug-log lines.
  • Env: ISOLATION_ENV only. CLAUDE_BIN overrides the binary.

Conclusion

Claude Code 2.1.318 (claude -p) tolerates an unquoted : in the middle of a frontmatter description, for agents and skills alike. The description reaches the model whole, the colon included. The fields after it (tools:) still apply, and no warning is logged. The frontmatter parser is more lenient than strict YAML for this case. That leniency is undocumented, so quoting the value stays the portable choice.

Not tested

  • Other placements of the colon: near the start (description: key: value), at the end of the line, or inside name: or other fields.
  • Whether the agent can be launched or the skill invoked. Only the listings were checked.
  • Agent SDK (bundled Claude Code) and interactive mode, including what /agents and /skills show.
  • Other characters that break strict YAML, such as #, a leading [ or {, or tabs.
