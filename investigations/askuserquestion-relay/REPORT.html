Can main relay a subagent's question with AskUserQuestion, then resume the same subagent?

A subagent cannot talk to the user. The pattern under test: the subagent returns a question, main asks the user with AskUserQuestion, then continues the same subagent instance with SendMessage to its agentId, passing the answer. Does the resume reach the original instance (with its context), and is it sync or async for main?

Setup

main  --Agent-->  clarifier  (returns QUESTION_FOR_USER)
main  --AskUserQuestion-->  fake user ("French")
main  --SendMessage(to: agentId)-->  same clarifier  (returns CLARIFIER_FINAL ... NONCE=<n>)

Fixture (this folder):

  • .claude/agents/clarifier.md: on its first run it draws a secret NONCE with Bash, keeps it hidden, and replies QUESTION_FOR_USER: ... with an OPTIONS: line. When it receives USER_ANSWER: ..., it waits 15 s and replies CLARIFIER_FINAL: <greeting> NONCE=<n>. Only the original instance knows the nonce, so a matching nonce proves the resume reached it.
  • prompts/askuser-main.md: tells main to relay the question with AskUserQuestion, then continue the same instance with SendMessage to the agentId.
  • The fake user always answers "French":
    • SDK: a canUseTool callback in askuser.ts.
    • claude -p: a PreToolUse hook, fake-user.mjs. -p offers AskUserQuestion only when the run has a permission host, so the run also passes fake-user-mcp.mjs as --permission-prompt-tool. That tool was never called; the hook answered every time.

Driver: askuser.ts (shared harness: lib/claude-home.mjs). Foreground is forced only by CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1 and CLAUDE_CODE_FORK_SUBAGENT=0. Allowed tools are Agent, Bash and SendMessage; AskUserQuestion goes through the fake user.

Run

npm install                                                         # repo root
node lib/claude-home.mjs investigations/askuserquestion-relay --check
npx tsx investigations/askuserquestion-relay/askuser.ts both 2      # sdk|cli|both, runs

Each run writes results/<YYYY-MM-DD>-<HHMM>-askuser/: per-run <name>.jsonl timelines, <name>.verdict.json, the CLI runs' <name>.settings.json / .mcp.json / .hooks.jsonl, askuser-summary.md (headed with the Claude Code versions that ran) and run.json. Session logs go to .claude-home/projects/sessions/.

The rerun is isolated (own config dir, no ancestor CLAUDE.md, only the clarifier agent) and uses the same prompt, verified identical to the original. The SDK bundles Claude Code, so SDK runs were 2.1.296 both times; the installed CLI had updated to 2.1.299 for the claude -p rerun.

Result

The pattern works, for the SDK and for claude -p (2 runs each, both times):

  • The SendMessage target equals the first spawn's agentId. There is one subagent transcript, holding both prompts, and the resumed reply carries the nonce from the first run: it is the same instance, with its context.
  • With background tasks disabled, SendMessage blocked main until the resumed run ended (17.5–18.9 s in the rerun, 18.3–22.0 s originally), then returned the report inline (Resumed agent. Its final report follows). Main got no task-notification turn and gave one result.
  • The resumed run's task_started event reports is_backgrounded: true even so.
  • SendMessage is a deferred tool, so main first loads it with ToolSearch. In the original SDK runs main loaded it before calling AskUserQuestion, in the rerun after; the order doesn't change the outcome.

Conclusion

Yes. Main can relay a subagent's question with AskUserQuestion and pass the answer back to the same instance with SendMessage to its agentId; the resumed subagent keeps its context. With background tasks disabled the resume is synchronous for main. Confirmed on Claude Code 2.1.296 (SDK and -p) and 2.1.299 (-p).

Not tested

  • The relay with background tasks enabled. Then a SendMessage resume runs in the background and the reply arrives as a later task-notification turn, as the resume.ts results in subagent-background-behaviour show for a plain resume.
  • Interactive mode, with a real user answering.
