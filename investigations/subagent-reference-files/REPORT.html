Does a subagent read, on demand and by direct path, the reference files named in its body?

Question

Claim under test (no doc sentence; it comes from the user's design idea): a subagent defined as .claude/agents/architect/architect.md can name files in its body, such as .claude/agents/architect/references/xxx.md, with "read xxx.md for more information". The subagent then reads them only when needed, by going straight to the path, without scanning the directory. Their content is not preloaded into its context, unlike an Agent Skill, whose description is always loaded.

Confirmed if the subagent's first tool call for a needed file is a Read that succeeds (no Glob, Grep or ls/find before it), if the file's NONCE is not in the subagent transcript before its first tool call, and if unneeded files are never read. Refuted if it has to scan, or if the content is already there without a Read. Run mode: claude -p only (no Agent SDK, no interactive).

Extension (2026-10-28): the same files named in a skill. Does the result hold when the reference files are named in a SKILL.md instead of the agent body? The subagent preloads the skill with skills: and has no Skill tool, so it gets no skill listing. Hypothesis: the injected skill message starts with Base directory for this skill: <absolute path> (seen in subagent-skill-awareness), so a path relative to the skill folder should resolve with one Read. Same confirm/refute criteria, claude -p only.

Conclusion

Partly confirmed. Files named in the agent body are not loaded in advance and are read only when the question needs them, so this is a progressive-disclosure mechanism with no cost for files that are not used. But the path must be written from the project root (.claude/agents/architect/references/xxx.md) for the subagent to read it with one Read. A path relative to the agent file (references/xxx.md) is read against the working directory, fails, and the subagent falls back to scanning. One run per scenario, so the exact failure sequence may vary.

Skills behave differently (extension). In a SKILL.md preloaded by a subagent, a path relative to the skill folder (references/xxx.md) is read with one direct Read. A root-relative path also works. The reason is the line Base directory for this skill: <absolute path> that Claude Code puts in front of every skill body. An agent body gets no such line, so the model only knows the cwd. Files are still read on demand only. The agent runs were on 2.1.309 and the skill runs on 2.1.312, one run each.

Not tested

  • Agent SDK and interactive modes.
  • Other models, other Claude Code versions (only 2.1.309 for agents, 2.1.312 for skills), repeated runs for variance.
  • A different cwd than the project root, and agents defined at user level (~/.claude/agents).
  • The no-folder anchor when the file name is not unique in the project (several references/naming.md): the search could pick the wrong one. Anchor variants were run once each.
  • Skill extension: the skill invoked through the Skill tool (by main or by a subagent) rather than preloaded; that path also injects the base-directory line (seen in subagent-skill-awareness), but was not run here. User-level and plugin skills. A rerun of the agent scenarios on 2.1.312.
